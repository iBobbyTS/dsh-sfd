# Optional efficiency notes

Load this reference only when the user requests cost/process analysis or a concrete diagnostic needs it. Routine work has **no mandatory baseline/per-Section/closeout efficiency diary** and no required manual signal-to-noise or call totals. Existing historical logs remain valid; do not delete them during migration.

## The four checkpoints

The historical baseline / per-section / anomaly / closeout labels may still organize an explicitly requested analysis; they are not required workflow transitions. Use existing actor, report, check and repair records instead of writing a second history.

Action-changing diagnosis is **not optional**: keep the third material repair-wave and second ineffective same-root-cause checks in [reviewer orchestration](reviewer-orchestration.md#review-progress-check-no-repeated-unproductive-work), and existing PLAN/recovery/Advisor stops. They do not require a separate cost essay.

## Record and report

When analysis is requested, report physical attempts separately from logical coverage, original repair waves, useful versus duplicate findings, invalidated evidence and only comparable measured cost/time. Preserve unknown data as UNKNOWN. Cache reads may already be included in provider input totals; do not double count.

Never dispatch a reviewer, rerun tests, delay acceptance or reconstruct fictional usage just to fill a log. Notes do not grant acceptance or change budget/authorization. Broader retrospective analysis belongs to general-audit when requested, not an automatic completion step.
